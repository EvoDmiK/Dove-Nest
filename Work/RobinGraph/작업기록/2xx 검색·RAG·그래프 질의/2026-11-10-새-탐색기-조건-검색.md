## 1. 작업 배경 및 문제 분석

### 발생 현상 / 요구사항
* RobinGraph 사용자가 원하는 조류를 찾고자 할 때, 자연어 대화 방식(예: `"숲에 사는 열매 먹는 새"`)은 대화형 편의성을 제공하지만 다음과 같은 한계가 존재함:
  1. 복잡한 다중 조건(예: 참새목 중 숲에 살고 열매와 곤충을 모두 먹는 한국 서식 조류)을 질의할 때 자연어 어휘 해석이나 마커 감지에서 모호성이 발생할 수 있음.
  2. 전체 조건과 각 조건별 데이터 커버리지(자료 유무), 구체적인 출처와 근거를 한눈에 대조하고 탐색하기 어려움.
* 이에 따라 직관적인 필터 컨트롤(체크박스, 라디오, 자동완성)을 통해 조건을 조합하고, 구조화된 그래프 쿼리로 정밀 탐색할 수 있는 **'조건으로 새 찾기(새 탐색기 / Bird Explorer)'** 기능이 요구됨.

### 설계 원칙 및 경계 검토
* **자연어 파서 우회**: 본 탐색기는 자연어 파서(LLM 프롬프트, Jev 의도 라우터, 임베딩 기반 유형 분류)를 경유하지 않음. 사용자가 UI에서 선택한 조건 객체를 직접 구조화된 질의 계약으로 변환하여 안전하고 빠른 응답을 보장함.
* **기존 구조화 그래프 검색 재사용**: 새로운 비표준 Cypher를 임의 생성하지 않고, 기존에 검증된 `graph_question_handler` 및 Cypher 쿼리 패턴을 재사용함.
* **분류군 필터 한정 (v1 계약)**: v1 계약에 따라 분류군은 목(order)·과(family)·속(genus)만 지원하며, 결과는 항상 **종(species) 단위**로 반환함. 종(species)이나 아종(subspecies) 학명/국명 입력 시 부모 범위로 넓히지 않고 HTTP 422(`taxon_rank_unsupported`)로 엄격히 거부함. UI는 입력 안내로 `"목·과·속 학명 한 단어 또는 검토된 한국어 목·과·속 이름"`을 명시함.
* **서식지 및 다중 먹이 AND 조건 및 비율 합산 정렬 (RG-214 연계)**: 서식지는 종별 대표값 특성상 AVONET 11개 값 중 1개만 허용함(복수 전송 시 422). 먹이 복수 선택 시 모든 먹이를 먹는 종만 필터링(AND, >0%)하며, 선택된 먹이 성분들의 비율을 합산한 값의 내림차순(DESC)으로 정렬함 (동점 시 한국어 이름순).
* **분포 스코프 4종 완전 지원 (RG-406 연계)**: `all`(전체), `korea`(국내 기록종), `outside`(국외 분포종), `unknown`(미판정) 스코프를 정확히 반영함.
* **자료 부재와 불일치 구분**: 조건에 맞는 데이터가 없는 빈 결과(`empty`)와 그래프 내 형질 자료 자체가 부족한 상태(`insufficient_data`)를 명확히 구분하여 사용자에게 투명하게 고지함.

## 2. 해결 방안 및 설계

### 1) 수용 기준 매트릭스 (Acceptance Criteria)
`/tmp/robingraph-bird-explorer-20261110/acceptance.md` 및 `contract.md` 기반 수용 기준:
1. **구조화 API 의도 보존**: `GET /v1/taxa/explore` 엔드포인트를 통해 자연어 의도/LLM/벡터 검색을 절대 호출하지 않으며, 클라이언트가 지정한 모든 조건이 서버에 그대로 전달되어 평가됨.
2. **분포 스코프 및 빈 조건**: 4개 스코프(`all`, `korea`, `outside`, `unknown`) 지원 및 조건 미선택 시 필터링된 도감 목록 반환.
3. **분류군 목·과·속 한정 및 종 단위 결과**: 목(order), 과(family), 속(genus) 학명/국명 입력만 지원하며, 결과는 항상 종 단위임. 종이나 아종 입력 시 부모 범위로 넓히지 않고 HTTP 422(`taxon_rank_unsupported`) 반환.
4. **복합 조건 질의**: 숲(서식지) + 열매(먹이) + Korea(분포) + 참새목(분류군) 조합 시 AND 조건 충족, 실제 증거 URL, 대표 서식지 일치, >0 먹이 비율, 합산 비율 내림차순 정렬.
5. **다중 먹이 정렬**: 열매 + 씨앗 동시 선택 시 두 먹이 모두 양수(>0), 합산 비율 기반 DESC 정렬, 신뢰도/출처 기준 준수.
6. **독립 조건 검증**: 서식지 단독, 먹이 단독, 분류군 단독, 분포 단독 조회가 각각 독립적으로 정상 동작.
7. **유효성 검증 및 422 에러**: 서식지 복수 전송, 잘못된 스코프/서식지/먹이 키, 먹이 중복, 빈 파라미터(`diet=`, `taxon=`), 종·아종 입력에 대해 HTTP 422 반환; 미해소 분류군과 빈 결과의 명확한 구분.
8. **자료 커버리지 및 페이징**: 자료 부재와 비일치를 시각적으로 구분하며, 20건 상한 및 `has_more` 공개.
9. **상태 공유 URL**: 공유 가능한 URL(Query string)을 통해 사용자가 선택한 필터 조합이 완벽히 복원됨.
10. **반응형 및 접근성**: 데스크톱(1280×800)과 모바일(390×844) 뷰포트에서 가로 넘침이 없으며 키보드 인터랙션 지원.
11. **도감 연계**: 결과 항목에서 조류 도감(Profile) 카드 클릭 시 정규 학명 및 현재 선택된 스코프가 보존되어 팝업 연결.
12. **기존 기능 무회귀**: 기존 채팅, 도감, 새소리(RG-409/RG-507) 기능에 영향 없음.

## 6. 한계 및 후속 과제

1. **중간 검증 단계의 한계**: 백엔드 로직 및 실제 TEST DB in-process 실사 검증은 통과했으나, UI 구현 및 실제 TEST 배포 E2E 브라우저 검증이 완료되기 전이므로 '진행 중' 상태를 유지하며, 최종 증거 확보 후 문서를 완료 상태로 전환함.
2. **단일 실행 소요 시간과 벤치마크 구분**: in-process Django ASGI 실측 소요 시간(0.226s ~ 0.551s)은 단일 실행 참고치이며, 전체 11k 종 목록 정렬에 대한 공식 벤치마크로 일반화하지 않음.
3. **자료 커버리지 한계**: EltonTraits, AVONET 등 기존 허용된 데이터 세트 범위 내에서 형질 조회가 수행되므로, 원천 자료가 없는 종의 경우 `insufficient_data`로 처리됨.
4. **프로덕션 배포 사용자 명시 승인 게이트**: 본 기능은 TEST 환경 검증 완료 후 사용자 명시 승인이 있을 때만 운영(NAS) 배포를 진행함.
