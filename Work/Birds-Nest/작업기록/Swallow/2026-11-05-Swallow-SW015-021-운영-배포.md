## 1. 작업 배경 및 문제 분석

뉴스 수집 주기, 멱등성·자동 리스크 관리·신선도 표시 등 SW-015~021 개발 변경의 운영 반영 요청.

## 2. 해결 방안 및 설계

기존 운영 n8n의 credential과 webhook 식별자를 보존하고 각 워크플로우를 비활성화·기존 실행 종료 확인 후 업데이트·재활성화했다. 오류 시 이전 정의 복원 경로를 마련했다. DB 적용 전 두 DB의 덤프를 확보했다.

## 3. 주요 구현 내용

마이그레이션 002~005는 각각 트랜잭션으로 순차 적용. MCP는 기존 이미지와 독립된 불변 릴리스로 빌드·배포. Grafana 테스트 파일을 Git Sync 감시 폴더 밖으로 이동한 `4cc06ec`를 push했다.

## 4. 검증 및 테스트 결과

- NAS 백업 `data.dump`, `n8n.dump`는 `pg_restore -l` 목록 검증을 통과했다. 복원 시험은 하지 않았다.
- 뉴스 첫 예약 실행 75885: success, DB 처리 이력 13 done / 1 retry. 공공데이터 티커 조회 노드에 오류 1건이 있었으며 retry 원인 및 후속 완료는 추가 확인이 필요하다.
- 시세 실행 75884: success, 리스크 평가 준비와 보유 리스크 평가 실행. 관측된 자동 청산 손익률은 익절 +5.08% 이상, 손절 -3.61% 이하.
- MCP 컨테이너 healthy, 인증된 목록 13개 및 포트폴리오 읽기 성공.
- Grafana Git Sync는 `4cc06ec` 기준 success, stock-monitor 패널 8 신규 쿼리 반영. 브라우저 렌더링은 미검증.
- Grafana SQL 테스트 이동 후 8/8 통과.

## 5. 배포 및 형상 관리

- 배포 전 덤프 및 n8n 워크플로우 JSON: `/volume3/Birds-Nest/docker-data/swallow-mcp/backups/20261105-swallow-predeploy-4ef45b3/` (접근 제한).
- MCP 이전 이미지 `swallow-mcp:4da38ee127f6819fba94c4c779234171fd7c02d5`; 이전 deploy.env 백업 보관.
- 운영 Grafana Git Sync `rgjc79` 브랜치를 main에서 `EvoDmiK/dev-swallow`로 변경했다. 현재 해당 브랜치의 향후 push가 자동으로 대시보드에 반영된다. 사용자가 PR #10을 main에 머지한 후 Git Sync를 main으로 되돌려야 한다.

## 6. 한계 및 후속 과제

- 첫 뉴스 실행의 retry 1건 후속 처리 결과 미확인.
- PR #10은 Draft이며 GitGuardian은 과거 테스트 비밀번호 커밋 탐지로 실패 상태다.
- Jenkins 및 에이전트가 있으나 Swallow 전용 Jenkins 파이프라인은 미구성.
- 운영 원천 시세의 모든 예외와 Grafana 브라우저 화면은 미검증.
